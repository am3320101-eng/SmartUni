## Overview

SmartUniPro is a university management backend that handles:

- **User management** with role-based access (ADMIN / INSTRUCTOR / STUDENT) — all in one unified `users` table
- **Smart attendance** — a student can only mark attendance if they are **physically within 50 metres** of the classroom **AND** have a valid **QR code** generated by their instructor
- **Course & session management**
- **Enrollment management**
- **Study materials** (PDF & video links per course)
- **AI interaction** history per student
- **Filtering & sorting** on every entity

## Database Schema

All users (admins, instructors, students) live in a **single `users` table**.
Role-specific fields are nullable and enforced at the service layer.

```
users
├── id, name, email, password, role
├── academic_number, level          ← STUDENT only
└── department                      ← INSTRUCTOR only

sessions         → course, instructor (user), location
attendances      → user (student), session  [UNIQUE: user_id + session_id]
enrollments      → user (student), session  [UNIQUE: user_id + session_id]
courses          → name, code
locations        → name, latitude, longitude
materials        → title, pdfUrl, videoUrl, course
ai_interactions  → question, answer, user (student)
```

## ⭐ Smart Attendance Flow

This is the core feature of SmartUniPro. A student **cannot fake attendance** — they must satisfy **both** conditions simultaneously:

```
┌─────────────────────────────────────────────────────────┐
│                  ATTENDANCE FLOW                        │
│                                                         │
│  INSTRUCTOR                                             │
│     │                                                   │
│     ▼                                                   │
│  POST /api/qr/generate/{sessionId}                      │
│     │                                                   │
│     ├── Reads session start time from DB                │
│     ├── Reads classroom location from DB                │
│     ├── Creates signed JWT (sessionId + locationId)     │
│     ├── Encodes JWT into QR image (PNG)                 │
│     └── Returns:                                        │
│          ├── rawToken  ← JWT string inside the QR       │
│          └── qrImageBase64 ← PNG to display on screen   │
│                                                         │
│  STUDENT (scans QR with phone)                          │
│     │                                                   │
│     ▼                                                   │
│  POST /api/attendance/mark                              │
│     Body: { studentId, sessionId, qrToken, lat, lon }   │
│     │                                                   │
│     ├── ✅ Check 1: User exists + role = STUDENT         │
│     ├── ✅ Check 2: Session exists                       │
│     ├── ✅ Check 3: Not already marked                   │
│     ├── ✅ Check 4: Session is currently active          │
│     ├── ✅ Check 5: QR token valid                       │
│     │      ├── Signature not tampered                   │
│     │      ├── Not expired                              │
│     │      ├── sessionId matches                        │
│     │      ├── locationId matches DB location           │
│     │      └── Nonce not reused (single-use QR)         │
│     └── ✅ Check 6: GPS within 50 metres of classroom    │
│                                                         │
│     Result → PRESENT or LATE (after 15-min grace)       │
└─────────────────────────────────────────────────────────┘
```

### ❌ Failure Responses

| Condition | HTTP | Message |
|---|---|---|
| QR expired | 400 | "QR code has expired" |
| QR wrong session | 400 | "QR code is not valid for this session" |
| QR location mismatch | 400 | "QR code location does not match this session's classroom" |
| QR already used | 400 | "QR code has already been used" |
| Student > 50m away | 400 | Distance + direction + how far to walk |
| Already marked | 409 | "Attendance already marked" |
| Session not started | 400 | "Session has not started yet" |
| Session ended | 400 | "Session has already ended" |

## QR + Location System

### How the QR token works

The QR token is a **signed JWT** containing:

```json
{
  "sessionId":  2,
  "locationId": 1,
  "nonce":      "uuid-v4-unique-per-generation",
  "iat":        1234567890,
  "exp":        1234568190
}
```

- **Single-use**: once a student scans it, the nonce is stored and the token is rejected for any future scan
- **Location-locked**: the `locationId` inside the token must match the session's classroom in the database — students cannot use a QR from a different room
- **Time-limited**: expires at `sessionStartTime + validityMinutes (default: 5 min)`

### GPS Distance (Haversine Formula)

The system calculates the real-world distance between the student's GPS coordinates and the classroom using the **Haversine formula** — accurate to within a few metres.

If the student is outside 50 metres, the response tells them exactly:
- Their current distance
- Which direction to walk
- How many more metres they need to move

## Setup & Run

### Prerequisites
- Java 17+
- Maven 3.9+
- Microsoft SQL Server (local or remote)

### 1. Create the database
```sql
CREATE DATABASE SmartUni;
CREATE LOGIN springuser WITH PASSWORD = '123456';
USE SmartUni;
CREATE USER springuser FOR LOGIN springuser;
ALTER ROLE db_owner ADD MEMBER springuser;
```

### 2. Clone and configure
```bash
git clone <repo-url>
cd smartunipro
```

Edit `src/main/resources/application.properties` if your DB credentials differ.

### 3. Run
```bash
./mvnw spring-boot:run
```

### 4. Access Swagger UI
```
http://localhost:8080/swagger-ui.html
```

## Filtering & Sorting

Every entity supports `GET /filter` with query parameters:

```
GET /api/attendance/filter?status=PRESENT&sessionId=2&sortBy=timestamp&sortDir=desc
GET /api/users/filter?role=STUDENT&level=2&sortBy=name&sortDir=asc
GET /api/sessions/filter?type=LECTURE&courseId=1&startTimeFrom=2025-09-01T08:00:00
GET /api/materials/filter?hasPdf=true&courseId=1
```

Available `sortDir` values: `asc` (default), `desc`
